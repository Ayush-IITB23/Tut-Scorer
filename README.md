## 1. Overview

This project builds a machine learning model that evaluates the actual quality of YouTube coding tutorials based on their metadata and engagement metrics. The goal is to filter out clickbait tutorials (e.g. "Learn Machine Learning in 10 Minutes!") that have high views but low educational value, and surface genuinely useful content.

The pipeline has three stages:

- **Data generation** — a synthetic CSV dataset of 200 tutorials is produced using an LLM prompt with realistic correlations.
- **Feature engineering** — derived features are computed from the raw CSV columns.
- **Model training & evaluation** — a Linear Regression model is trained and used to predict quality scores and rank tutorials.

```bash
Video_Title, Video_Desciption, Upload_Date, Duration_Minutes, View_Count, Like_Count, Comment_Count, Channel_Subscriber_Count, Actual_Quality_Score

To make this dataset useful for a quality prediction model, you must inject realistic, distinct patterns. Distribute the 200 rows roughly as follows:

- All metrics (views, likes, etc.) must be realistic integers, scaling logically with Channel_Subscriber_Count.

- Only output the raw CSV data. Do not include any conversational text, markdown formatting, or explanations before or after the CSV. Start directly with the header row.
```

Add a new column named `Engagement_Rate` in the generated csv file and automate the calculations using the formula `Engagement_Rate = (Like_Count + Comment_Count) / View_Count` which can be easily done by typing in the formula of that cell and then dragging till last cell for automatic fill up.

`Engagement_Rate` is the most important derived feature. It is defined as:

```
Engagement_Rate = (Like_Count + Comment_Count) / View_Count
```

This normalises engagement by views, so a video with 1,000 likes out of 10,000 views (ratio = 0.10) is correctly rated higher than a video with 50,000 likes out of 5,000,000 views (ratio = 0.01), even though the second has 50× more likes in absolute terms.

This is exactly how clickbait is penalised mathematically: clickbait maximises views through sensational titles, but viewers who feel misled do not like or comment, collapsing the `Engagement_Rate` and therefore the predicted quality score.

## 4. How the Script Works

### 4.1 Loading the Data

The script reads `tutorials.csv` using pandas. Six input features are selected:

| Feature | What it captures |
|---------|-----------------|
| `Duration_Minutes` | Length of the video; very short videos are likely superficial |
| `View_Count` | Total views; high views alone do not indicate quality |
| `Like_Count` | Number of likes; reflects genuine approval from viewers |
| `Comment_Count` | Number of comments; indicates discussion and engagement depth |
| `Engagement_Rate` | Derived: (Likes + Comments) / Views; key ratio signal |
| `Channel_Subscriber_Count` | Channel authority; larger channels have more resources |

### 4.2 Train/Test Split

The data is split 80/20 using `train_test_split` with `random_state=42` to ensure reproducibility. The model trains on 160 rows and is evaluated on 40 unseen rows.

### 4.3 Linear Regression Model

Linear Regression fits a straight-line (hyperplane) relationship between the input features and the target variable (`Actual_Quality_Score`):

```
Predicted Score = w₁×Duration + w₂×Views + w₃×Likes + w₄×Comments + w₅×EngagementRate + w₆×Subscribers + b
```

The model learns weights `w₁…w₆` and bias `b` by minimising Mean Squared Error (MSE) on the training set. MSE is the average of `(actual − predicted)²` across all training examples. This has a closed-form solution so no iterative training loop is needed.

### 4.4 Evaluation — Mean Absolute Error

After training, the model predicts scores on the test set. Mean Absolute Error (MAE) is computed:

```
MAE = (1/n) × Σ |actualᵢ − predictedᵢ|
```

MAE tells us, on average, how many quality score points the model is off by. Lower is better.

### 4.5 Feature Weights
The script prints each feature's learned coefficient sorted by value & also the complete predicted quality score equation in the form Predicted Quality Score = (w₁ × Feature1) + (w₂ × Feature2) + ... + b. A positive weight means higher values of that feature push the predicted score up; a negative weight means the opposite. For example: A positive weight means higher values of that feature push the predicted score up; a negative weight means the opposite. For example:

- **High `Engagement_Rate`** → large positive weight → quality tutorials get high engagement relative to views
- **High `View_Count` alone** → small or negative weight → viral clickbait has high views but low quality

### 4.6 Ranking & Top 10

The trained model predicts a quality score for every tutorial in the full dataset. Scores are clipped to `[0, 100]` to handle any out-of-range predictions. Tutorials are then sorted in descending order and the top 10 are printed with their title, view count, predicted score, and actual score for comparison.
